# Систолический gaxpy на кольце

Параллельная реализация операции **дахру / gaxpy** ([[gaxpy-и-saxpy]]) $z = Ax + y$ на
топологии **процессорное кольцо** ([[топологии-сетей]]). Здесь $z,y\in\mathbb{R}^{n\times1}$,
$x\in\mathbb{R}^{m\times1}$, $A\in\mathbb{R}^{n\times m}$. Векторы и матрица разбиваются на
$p$ блоков ($p$ — число задач): $z_i,y_i\in\mathbb{R}^{\alpha\times1}$,
$x_j\in\mathbb{R}^{\beta\times1}$, $A_{ij}\in\mathbb{R}^{\alpha\times\beta}$,
$\alpha=n/p$, $\beta=m/p$ ([[Параллельные алгоритмы]] §1.1). Способ распределения блоков
матрицы $A$ определяет вид алгоритма.

## Систолический принцип

**Систоличность** — потактовое продвижение данных по кольцу: на каждой итерации задача
сначала **отправляет** блок правому соседу и **принимает** блок от левого, и лишь затем
выполняет арифметику. Два следствия-недостатка ([[Параллельные алгоритмы]] §1.1):
- арифметику приходится **предварять** коммуникацией (даже когда нужный блок уже лежит в
  памяти — как на последней итерации; это вынужденный **простой**/лишний обмен);
- одновременная отправка во всех задачах перегружает сеть; «разумное» чередование
  приём/отправка по чётности задач невозможно — приём всегда стоит **за** отправкой.

При кодировании эти недостатки легко устраняются (например, сократить число
коммуникаций с $p$ до $p-1$, задача 1.1.1).

## Вариант 1. Распределение $A$ по блочным строкам

Задача $\mu$ вычисляет блок $z_\mu = A_\mu x + y_\mu$ через **блочное скалярное
произведение** $\mu$-й блочной строки $A_\mu$ на вектор $x$:
$$z_\mu = \sum_{j=1}^{p} A_{\mu j}\, x_j + y_\mu. \tag{1}$$

![](../../markdown/Головашкин_Д_Л_Параллельные_алгоритмы_вычислительной_линейной_алгебры/_page_6_Figure_1.jpeg)

Рис. Распределение $A$ по блочным строкам: а — данные в памяти задачи 2 ($p=5$);
б — топология коммуникаций (кольцо).

**Без коммуникаций** (алгоритм 1): в памяти задачи $\mu$ хранится вся блочная строка
$A_\mu$ и **весь** вектор $x$ (он дублируется во всех задачах — плата за отсутствие
обменов). На итерации $j$ все задачи одновременно домножают $j$-й блочный столбец $A$ на
$x_j$.

**На кольце** (алгоритм 2): чтобы не дублировать $x$, задаче $\mu$ достаётся лишь блок
$x_\mu$, а блоки $x$ гоняются по кольцу. На каждой из $p$ итераций:
```
send(x_loc, right)            % отправка блока x правому соседу
recv(x_loc, left)             % приём блока x от левого соседа
τ = μ - j; if τ≤0 then τ=τ+p  % индекс полученного блока x_τ
y_loc = y_loc + A_loc(:,a)·x_loc   % слагаемое τ из (1)
```
За $p$ итераций через задачу $\mu$ проходят **все** блоки $x$. Порядок суммирования в
разных задачах разный (у каждой свой порядок индексов $\tau$), но результат верен.
Соседи: `left = μ-1`, `right = μ+1`; у первой задачи левый сосед — задача $p$, у
последней правый — задача 1.

## Вариант 2. Распределение $A$ по блочным столбцам

Здесь $z$ — **линейная комбинация блочных столбцов** $A$. При $\omega_j = A_j x_j$:
$$z_\mu = \sum_{j=1}^{p} \omega_j(\text{row}) + y_\mu, \tag{2}$$
где $\omega_j\in\mathbb{R}^{n\times1}$, $\text{row}=(\mu-1)\alpha+1:\mu\alpha$.

![](../../markdown/Головашкин_Д_Л_Параллельные_алгоритмы_вычислительной_линейной_алгебры/_page_10_Picture_4.jpeg)

Рис. Распределение $A$ по блочным столбцам (именованы блоки задачи 2, $p=5$).

![](../../markdown/Головашкин_Д_Л_Параллельные_алгоритмы_вычислительной_линейной_алгебры/_page_11_Picture_4.jpeg)

Рис. Иллюстрация к ф. (2) при $\mu=2$, $p=5$.

**На кольце** (алгоритм 3): в памяти задачи $\mu$ — блочный столбец $A_\mu$ и блок
$x_\mu$. Сначала формируется $\omega = A_{loc}\,x_{loc} = \omega_\mu$, затем векторы
$\omega$ продвигаются по кольцу:
```
ω = A_loc · x_loc             % формирование ω_μ
for j=1:p
  send(ω, right); recv(ω, left)
  y_loc = y_loc + ω(row)      % сложение по ф. (2)
end for
```
Алгоритм **проще** второго: при сложении не важно, в какой задаче сформирован полученный
$\omega$ (сложение коммутативно, номер задачи учитывать не нужно).

## Число шагов, коммуникаций, объём

- **Итераций / коммуникаций:** $p$ пар «отправка–приём» в каждой задаче (можно сократить
  до $p-1$).
- **Объём пересылок (на итерацию):**
  - блочные строки (алг. 2) — пересылается блок $x_{loc}$ из $\beta$ элементов;
  - блочные столбцы (алг. 3) — пересылается вектор $\omega$ из $n$ элементов.
  Упрощение алгоритма 3 оплачено **ростом объёма коммуникаций в $n/\beta$ раз** при том
  же их количестве ([[Параллельные алгоритмы]] §1.1).
- **Простои:** систоличность вынуждает лишний обмен на последней итерации (операции с
  $x_\mu$ можно было бы сделать до первой итерации).

Выбор: вариант по блочным строкам выгоден с учётом строчного хранения и пакетной
передачи; по блочным столбцам — проще, но дороже по трафику (задачи 1.1.2).
