# Метод параллелепипедов

Метод [[автоматическое-распараллеливание|автоматического распараллеливания]] **циклических**
участков: [[пространство-итераций]] покрывается $k$-мерными параллелепипедами; векторы внутри
выбранного параллелепипеда задают задачи параллельного алгоритма
([[Модели]] §2.2.2, [[Лекции]] §2.2.2).

В отличие от [[метод-пирамид|метода пирамид]]:

- **позволяет** работать с **простыми** (одиночными) циклами;
- допускает (в общем случае) **коммуникации** между задачами;
- требует **линейности** участия параметров цикла в теле;
- покрытие — **разбиение**, можно строить несколько вариантов и **оптимизировать** по
  ускорению.

## Этапы

1. В декартовом виде строится пространство итераций с отношениями зависимости и следования.
2. Ищутся **разбиения** пространства на параллелепипеды размерности не выше $K$, каждый из
   которых содержит **только независимые** векторы. Этапы 3–4 проходятся для каждого разбиения.
3. Выбирается параллелепипед **максимального объёма** со сторонами $p_1,\dots,p_K$ (длина =
   разница координат крайних векторов по направлению $+1$). На рёбрах строится **новая
   декартова система координат** с началом $(1,1,\dots,1)$. Каждому вектору $\mathbf i$ внутри
   ставится в соответствие задача с вектором-номером $(g_1,\dots,g_K)$, где $g_k$ — $k$-я
   координата $\mathbf i$ в новой системе. Если размерность параллелепипеда меньше $K$, по
   «фиктивным» направлениям $g_k=1$ и $p_k=1$. Число задач (для прямоугольного):
   $$p=\prod_{k=1}^{K} p_k.$$
4. Все векторы пространства распределяются по задачам: из каждого параллелепипеда разбиения к
   одной задаче — **не более одного** вектора. Внутри задачи векторы упорядочены по отношению
   следования. При необходимости задаётся синхронизация (send/recv в нотации Голуба). Общий вид
   параллельной конструкции (Алгоритм 2.4):
   ```
   for i_1 = g_1:p_1:n_1
     ...
       for i_K = g_K:p_K:n_K
         T(i_1, ..., i_K)
         <синхронизация>
       end for
   end for
   ```
5. Построенные алгоритмы сравниваются, выбирается лучший по ускорению.

## Пример 1: простой цикл (Программа 2.3)

```
for i = 1:10
  x(i) = f(x(i-4))
end for
```
Пространство $I=\{(i):\ 1\le i\le 10\}$ (векторы — скаляры). Зависимость: $i$ зависит от $i-4$.
Возможные покрытия и их ускорения:

- по одному вектору $\{1\}\cup\{2\}\cup\dots\cup\{10\}$ — **вырожденное** (всё последовательно);
- парами $\{1,2\}\cup\{3,4\}\cup\dots\cup\{9,10\}$ — **двухзадачный** Алгоритм 2.2
  (`for i=μ:2:10`), нечётные зависят только от нечётных, чётные от чётных — **без
  коммуникаций**, $S=10/5=2$;
- $\{1,2,3,4\}\cup\{5,6,7,8\}\cup\{9,10\}$ — **четырёхзадачный** Алгоритм 2.3 (`for i=μ:4:10`):
  задачи 1,5,9 / 2,6,10 / 3,7 / 4,8; **синхронизации не требуется**, $S=10/3$.

Удачное распределение векторов по задачам избавляет от коммуникаций; неудачное (например
1,6,9 и 2,5,10) их порождает ([[Модели]] §2.2.2).

Название: в 1D подмножества — отрезки на прямой, в 2D — параллелограммы, в 3D —
параллелепипеды.

## Пример 2: двойной цикл (Программа 2.4)

```
for i_1 = 1:7
  for i_2 = 1:3
    x(i_1,i_2) = f(x(i_1-2, i_2-1))
  end for
end for
```
$I=\{(i_1,i_2):\ 1\le i_1\le 7,\ 1\le i_2\le 3\}$. Рассмотрены три разбиения:

![Пространство итераций двойного цикла и три разбиения](../../markdown/Головашкин_Д_Л_Модели_в_теории_параллельных_вычислений_2019/_page_77_Figure_2.jpeg)

- **Разбиение «а»** (Алгоритм 2.5): максимальный параллелепипед $p_1=2,\ p_2=1$ (фиктивная
  сторона) $\Rightarrow$ 2 задачи $(g_1,g_2)$: $(1,1)$ — нечётные $i_1$, $(2,1)$ — чётные.
  **Без синхронизации**, $S=21/12=1{,}75$.
- **Разбиение «б»** (Алгоритм 2.6): $p_1=7,\ p_2=1$ $\Rightarrow$ 7 задач $(g_1,1)$,
  $1\le g_1\le 7$. **Нужна синхронизация**: задачи $g_1\le2$ только отправляют, $g_1\ge6$
  только принимают, остальные — и то и другое. $S=21/3=7$. Топология коммуникаций — две
  несвязанные линии (нечётные / чётные $g_1$).
  ```
  for i_1 = g_1:p_1:7
    for i_2 = g_2:p_2:3
      if (i_1-2) >= 1 and (i_2-1) >= 1 then recv(x(i_1-2,i_2-1),(g_1-2,g_2)) end if
      x(i_1,i_2) = f(x(i_1-2,i_2-1))
      if (i_1+2) <= 7 and (i_2+1) <= 3 then send(x(i_1,i_2),(g_1+2,g_2)) end if
    end for
  end for
  ```
- **Разбиение «в»** (третий алгоритм): прямоугольник $p_1=2,\ p_2=3$ $\Rightarrow$ 6 задач
  $(g_1,g_2)$, $1\le g_1\le2$, $1\le g_2\le3$. Адресаты коммуникаций меняются на
  $(g_1,g_2-1)$ при приёме и $(g_1,g_2+1)$ при отправке. $S=21/4=5{,}25$. Топология — две
  линии с одинаковыми $g_1$.

![Топология коммуникаций алгоритмов для Программы 2.4](../../markdown/Головашкин_Д_Л_Модели_в_теории_параллельных_вычислений_2019/_page_81_Figure_2.jpeg)

Условные переходы для send/recv в теле цикла снижают производительность, но сохранены ради
методической наглядности (общая форма Алгоритма 2.4). Отношение зависимости (а значит условия
коммуникаций) **не зависит** от выбора покрытия. На практике число задач много больше числа
устройств, поэтому задачи **объединяют** ([[Лекции]] §2.2.2).

## Связи

- Альтернатива — [[метод-пирамид]] (без коммуникаций, допускает нелинейные индексы, но
  единственное покрытие и дублирование).
- Общая модель и критерий $S\to\max$ — [[пространство-итераций]].
- Нотация Голуба send/recv, укрупнение задач — [[модель-задача-канал]].
- Ациклические аналоги — [[стандартный-граф-и-граф-зависимостей]],
  [[ЯПФ-и-параллельный-алгоритм]].
- Метрика — [[ускорение-эффективность-масштабируемость]].
- Часть общей схемы — [[автоматическое-распараллеливание]].

## Расхождения

- **Нумерация параграфа.** В методичке метод параллелепипедов — **§2.2.2**, в лекциях —
  **§2.2.2** тоже, но порядок изложения обратный: лекции дают пирамиды (§2.2.1) раньше
  параллелепипедов (§2.2.2), а методичка — параллелепипеды (§2.2.2) раньше пирамид (§2.2.3).
  Содержание совпадает; приоритет у методички.
- Числовые примеры лекций ($S=2$, $S=10/3$) совпадают с примером 1 методички; подробные
  оценки ($S=1{,}75;\ 7;\ 5{,}25$) и второй пример — только в методичке.
