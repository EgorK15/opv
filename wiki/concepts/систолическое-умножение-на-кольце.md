# Систолическое умножение матриц на кольце

Параллельное умножение матриц $D = C + AB$ на топологии **процессорное кольцо**
([[топологии-сетей]]). Здесь $D,C\in\mathbb{R}^{n\times m}$, $A\in\mathbb{R}^{n\times q}$,
$B\in\mathbb{R}^{q\times m}$; блоки $D_{ij},C_{ij}\in\mathbb{R}^{\alpha\times\beta}$,
$A_{ij}\in\mathbb{R}^{\alpha\times\gamma}$, $B_{ij}\in\mathbb{R}^{\gamma\times\beta}$,
$\alpha=n/p$, $\beta=m/p$, $\gamma=q/p$, $p$ — число задач
([[Параллельные алгоритмы]] §1.2). Алгоритмы прямо продолжают
[[систолический-gaxpy-на-кольце]]: тот же систолический принцип потактового продвижения
блоков по кольцу.

Два варианта различаются ориентацией: какой блочный фрагмент $D$ считает задача и какую
матрицу ($A$ или $B$) гоняют по кольцу.

## Столбцово-ориентированный алгоритм (пересылка блочных столбцов $A$)

Задача $\mu$ вычисляет **блочный столбец** $D_\mu$ через линейную комбинацию блочных
столбцов $A$:
$$D_\mu = C_\mu + AB_\mu = C_\mu + \sum_{j=1}^{p} A_j\, B_{j\mu}, \tag{4}$$
где $D_\mu,C_\mu\in\mathbb{R}^{n\times\beta}$, $B_\mu\in\mathbb{R}^{q\times\beta}$,
$A_j\in\mathbb{R}^{n\times\gamma}$.

![](../../markdown/Головашкин_Д_Л_Параллельные_алгоритмы_вычислительной_линейной_алгебры/_page_13_Figure_9.jpeg)

Рис. Иллюстрация к ф. (4) при $\mu=2$, $p=5$.

Матрица $A$ нужна всем задачам целиком. **Без коммуникаций** (алгоритм 4): $A$
дублируется в памяти каждой задачи, по кольцу ничего не гоняется.

**На кольце** (алгоритм 5): $A$ распределяется по блочным столбцам, и эти столбцы
пересылаются между задачами — для больших матриц, не помещающихся в память одной задачи.
По структуре алгоритм 5 почти совпадает с алгоритмом 2 из
[[систолический-gaxpy-на-кольце]]:
```
for j=1:p
  send(A_loc, right); recv(A_loc, left)   % продвижение блочного столбца A
  τ = μ - j; if τ≤0 then τ=τ+p            % индекс полученного блока A_τ
  C_loc = C_loc + A_loc · B_loc(a,:)      % слагаемое τ из (4)
end for
```
Порядок суммирования в задачах разный (как в алгоритме 2), но результат верен в силу
коммутативности сложения матриц. По завершении в $C_{loc}$ задачи $\mu$ лежит блочный
столбец $D_\mu$.

## Строчно-ориентированный алгоритм (пересылка блочных строк $B$)

При $n \gg m$ элементов в $A$ намного больше, чем в $B$, — выгоднее гонять по кольцу
блоки $B$. Задача $\mu$ вычисляет **блочную строку** $D_\mu$ через линейную комбинацию
блочных строк $B$:
$$D_\mu = C_\mu + A_\mu B = C_\mu + \sum_{i=1}^{p} A_{\mu i}\, B_i, \tag{5}$$
где $D_\mu,C_\mu\in\mathbb{R}^{\alpha\times m}$, $A_\mu\in\mathbb{R}^{\alpha\times q}$,
$B_i\in\mathbb{R}^{\gamma\times m}$.

![](../../markdown/Головашкин_Д_Л_Параллельные_алгоритмы_вычислительной_линейной_алгебры/_page_15_Figure_5.jpeg)

Рис. Иллюстрация к ф. (5) при $\mu=2$, $p=5$.

Алгоритм 6 отличается от алгоритма 5 минимально — по кольцу продвигаются блочные строки
$B$:
```
for j=1:p
  send(B_loc, right); recv(B_loc, left)   % продвижение блочной строки B
  τ = μ - j; if τ≤0 then τ=τ+p
  C_loc = C_loc + A_loc(:,a) · B_loc       % слагаемое τ из (5)
end for
```

## Выбор и оценки

- **$n \gt m$** — выгоднее алгоритм 5 (пересылаем меньшую матрицу $A$ по столбцам);
  **$n \lt m$** — алгоритм 6 (пересылаем $B$ по строкам).
- **Хранение / язык:** столбцовое хранение → язык со столбцовой схемой массивов
  (фортран); строчное → строчная схема (Си). Это упрощает начальное распределение.
- **Коммуникации:** $p$ пар «отправка–приём» на задачу; объём — целая матрица $A$ или
  $B$ за все итерации. (Сравнение с тором: на торе $2\sqrt{p}$ пар и меньший объём —
  см. [[систолическое-умножение-на-торе]].)
- Систолические недостатки те же, что и у [[систолический-gaxpy-на-кольце]] (обмен
  предваряет арифметику; число коммуникаций можно сократить до $p-1$, задача 1.2.2).
