# Умножение матриц (векторные и блочные алгоритмы)

Классическое умножение матриц $C = AB$ (точнее, накапливающая операция $C = C + AB$):
для $A\in\mathbb{R}^{n\times q}$, $B\in\mathbb{R}^{q\times m}$, $C\in\mathbb{R}^{n\times m}$
$$c_{ij} = \sum_{k=1}^{q} a_{ik} b_{kj}.$$
Это самая употребимая матричная операция третьего уровня и одновременно самая
ресурсоёмкая: арифметическая сложность $O(n^3)$ ([[Векторные алгоритмы]] §1.2).
Тема этой страницы — как одну и ту же формулу записать в разных векторных формах
(сворачивая тройной цикл в [[gaxpy-и-saxpy]], скалярное произведение или
[[модификация-матрицы-внешним-произведением]]) и как блочность снижает
коммуникационные издержки.

## Тройной цикл и его свёртка

Скалярный `ijk`-алгоритм («умножение по определению»):
```
for i=1:n
  for j=1:m
    for k=1:q
      C(i,j) = C(i,j) + A(i,k)B(k,j)
    end for
  end for
end for
```
Векторизация — это «сворачивание» одного цикла: параметр свёрнутого цикла
заменяется на двоеточие (проход по всему вектору). **Внутренний** цикл задаёт
векторную операцию и способ доступа к памяти, **внешний** — матричную операцию
([[Векторные алгоритмы]] §1.2).

### `ijk` → скалярное произведение (строчное дахру / gaxpy)

Свернём внутренний цикл по `k`. Получаем скалярное произведение строки $A$ на
столбец $B$ (первое слагаемое $C(i,j)$ упраздняется — оно для скалярного
произведения не нужно):
```
for i=1:n
  for j=1:m
    C(i,j) = A(i,:)·B(:,j)      % скалярное произведение
  end for
end for
```
Свернув ещё и цикл по `j`, приходим к матричной форме — **строчному дахру**
([[gaxpy-и-saxpy]]):
```
for i=1:n
  C(i,:) = A(i,:)·B             % строчное gaxpy
end for
```
Векторная операция — скалярное произведение, матричная — строчное `gaxpy` (дахру),
способ доступа к памяти **смешанный** (строки $A$ и столбцы $B$ одновременно), что
замедляет вычисления ([[Векторные алгоритмы]] §1.2; [[Лекции]] §3.1).

### `jki` → столбцовое saxpy (столбцовое gaxpy)

Внутренний цикл по `i` — это столбцовое [[gaxpy-и-saxpy|saxpy]], доступ по столбцам:
```
for j=1:m
  for k=1:q
    C(:,j) = C(:,j) + A(:,k)B(k,j)   % столбцовое saxpy
  end for
end for
```
Матричная форма — столбцовое `gaxpy`: `C(:,j) = A·B(:,j)`. Уместен столбцовый способ
хранения матриц (язык Си). В `jki`, в отличие от `ijk`, первое слагаемое при
векторизации не упраздняется — `j`-й столбец $C$ обновляется многократно
([[Векторные алгоритмы]] §1.2).

### `kij` → строчное saxpy и модификация матрицы

Внутренний цикл по `j` — строчное `saxpy`, доступ по строкам:
```
for k=1:q
  for i=1:n
    C(i,:) = C(i,:) + A(i,k)B(k,:)   % строчное saxpy
  end for
end for
```
Свёртка цикла по `i` доводит алгоритм до матричной операции — **модификации матрицы
внешним произведением** ([[модификация-матрицы-внешним-произведением]]):
```
for k=1:q
  C = C + A(:,k)B(k,:)               % внешнее произведение
end for
```

### Классификация (таблица 1)

Перебор порядка трёх циклов даёт **шесть** алгоритмов с разными свойствами. Две
системы наименования ([[Векторные алгоритмы]] §1.2):
- по **матричной/векторной операции** (классификация Голуба) — информативная;
- по **порядку циклов** `ijk`, `jki`, … (классификация Ортеги) — лаконичная.

| название | векторная операция | матричная операция | доступ к памяти |
|----------|--------------------|--------------------|-----------------|
| `ijk`/`jik` | скалярное произведение | строчное/столбц. gaxpy | смешанный |
| `jki`/`ikj` | saxpy | gaxpy | по столбцам / по строкам |
| `kij`/`kji` | saxpy | модификация матрицы | по строкам / по столбцам |

Отбор «лучшего»: `ijk`, `jik` исключают из-за смешанного доступа; `kij`, `kji` —
из-за того что внешнее произведение уступает дахру по объёму коммуникаций
память—память. Остаются `jki` (оптимален при столбцовом хранении) и `ikj` (при
строчном) ([[Векторные алгоритмы]] §1.2).

## Блочный алгоритм

Самыми лучшими признаются **блочные алгоритмы**: на каждый обмен данными приходится
больше вычислений. Цитата Голуба: умножение $k\times k$ матриц занимает $2k^3$ флопов,
вовлекая лишь $2k^2$ элементов данных ([[Векторные алгоритмы]] §1.2, цит. [2]).
См. подробно [[блочные-алгоритмы]].

Память упрощается до двух уровней: «быстрая» (кэш) и «медленная» (ОЗУ). Матрицы целиком
в кэш не помещаются. Критерий: над однажды загруженными в «быструю» память данными
производить максимум арифметики до выгрузки — то есть опираться на операцию **третьего**
уровня (умножение блоков).

Квадратные $n\times n$ матрицы, блоки $\alpha\times\alpha$, $\alpha = n/N$, $N$ — блочный
размер, $N^2$ блоков. Блочный аналог формулы:
$$C_{i_b j_b} = \sum_{k_b=1}^{N} A_{i_b k_b} B_{k_b j_b}.$$

```
for i_b=1:N
  i = (i_b-1)α+1 : i_b·α
  for j_b=1:N
    j = (j_b-1)α+1 : j_b·α
    { блок C(i,j) := 0 }
    for k_b=1:N
      k = (k_b-1)α+1 : k_b·α
      { считать блок A(i,k) в «быструю» память }
      { считать блок B(k,j) в «быструю» память }
      C(i,j) = C(i,j) + A(i,k)B(k,j)
    end for
    { записать блок C(i,j) в «медленную» память }
  end for
end for
```

Собственная схема хранения — **по блокам** (рис. 3): элементы одного блока лежат рядом и
извлекаются с единичным шагом.

### Сложность и коммуникации

- **Арифметика:** $O(n^3)$; блочный размер $N$ на неё **не влияет**.
- **Коммуникации (объём пересылок):** $(N\cdot 2\alpha^2 + \alpha^2)N^2 = n^2(2N+1)$.
  Меньше $N$ — меньше коммуникаций.
- **Ограничение кэша** ($M$ элементов, три блока сразу): $3(n/N)^2 \le M$, откуда
  $N \ge n\sqrt{3/M}$. Оптимум при полном заполнении кэша:
  $$N_{\text{opt}} \approx n\sqrt{3/M}.$$
- Перестановка циклов в блочном алгоритме не меняет матричную операцию; алгоритмы с
  третьим циклом по $k_b$ оптимальны, для прочих коммуникации растут на треть
  ([[Векторные алгоритмы]] §1.2).

«Быстрые» алгоритмы снижают и саму $O(n^3)$: [[метод-Винограда]] (вдвое меньше
умножений), [[метод-Штрассена]] ($O(n^{2.807})$).
