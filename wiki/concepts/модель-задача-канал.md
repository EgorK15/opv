# Модель задача/канал

Модель алгоритмов. Под алгоритмом (по А. А. Маркову) понимают точное предписание,
определяющее вычислительный процесс, ведущий от варьируемых исходных данных к
искомому результату [[Модели]] §1.2; свойства алгоритма — **определённость**,
**массовость**, **результативность** (см. персону [[Марков]]).

## Задача и канал

Модель задача/канал — ориентированный граф [[Модели]] §1.2.1 (рис. 1.7).

- **Задача** (окружность) — последовательный набор инструкций и данных, над которыми
  инструкции исполняются. Внутри задачи инструкции исполняются строго одна за другой,
  как в последовательном алгоритме.
- **Канал** (дуга) — средство пересылки данных между задачами.

Параллельность обеспечивается одновременным исполнением инструкций в нескольких
задачах. В ходе работы алгоритма задачи могут порождаться и упраздняться по
инструкциям других задач.

![Пример описания алгоритма в модели задача/канал](../../markdown/Головашкин_Д_Л_Модели_в_теории_параллельных_вычислений_2019/_page_16_Picture_3.jpeg)

### Два правила каналов [[Лекции]] §1.2

1. **Ориентированность.** Перемещение данных по каналу всегда в одну сторону. Для
   обратной пересылки нужен другой канал между теми же задачами.
2. **FIFO.** Отправления по одному каналу идут по принципу «первый вошёл — первый
   вышел» (метафора «вагончики»).

## Свойства коммуникаций

Типы коммуникаций, характеризующие алгоритм [[Модели]] §1.2.1, [[Лекции]] §1.2:

- **Синхронные / асинхронные.** Синхронная отправка/приём исключает любые иные
  действия в задачах до окончания приёма; при асинхронной следующие инструкции
  выполняются, не дожидаясь завершения. Возможны смешанные случаи (асинхронная
  отправка + синхронный приём и наоборот).
- **Локальные / глобальные.** У локальных число соседей характерной задачи слабо
  (не сильнее логарифмической) зависит от общего числа задач: соседи
  $\le \lceil \log_2 p \rceil$ (см. [[топологии-сетей]]). Локальны линия, кольцо,
  решётка, тор, дерево, гиперкуб; глобальны полносвязная топология и звезда.
- **Статические / динамические.** Статические — топология не зависит от данных и
  промежуточных результатов; динамические возникают/упраздняются по ходу расчёта.
- **Регулярные / нерегулярные.** Регулярные совпадают с известной (или планируемой)
  сетевой конфигурацией; нерегулярные требуют дополнительной маршрутизации через
  промежуточные узлы, что замедляет расчёт.

## Нотация Джина Голуба

Форма Дж. Голуба дополняет модель задача/канал, конкретизируя содержание задач
(Голуб называет задачу процессором) [[Модели]] §1.2.2. Синтаксис почти совпадает с
MATLAB: вектор $a(1:n)$, нечётные элементы $a(1:2:n)$, матрица $A(1:n,1:n)$, её блок
$A(n_1:n_2, n_3:n_4)$.

Один набор инструкций пишется для всех задач; в зависимости от номера задачи фрагменты
исполняются или пропускаются. Описание делится на две части:

1. **Инициализация** — число задач $p$, номер конкретной задачи $\mu$, распределение
   начальных данных, конкретизация соседей $\mu$-й задачи.
2. **Собственно алгоритм** на языке Голуба.

### Соседи

Из топологий Голуб особо выделяет линию, кольцо, решётку и тор [[Модели]] §1.2.2:

- одномерный случай (задача $\mu$): $left = \mu - 1$, $right = \mu + 1$;
- двумерный случай (задача $(\mu, \lambda)$):
  $west = (\mu, \lambda - 1)$, $east = (\mu, \lambda + 1)$,
  $north = (\mu - 1, \lambda)$, $south = (\mu + 1, \lambda)$.

На кольце для $\mu = 1$ левым соседом будет задача $p$, для $\mu = p$ правым — задача
$1$ (аналогично определяются крайние задачи тора).

### Операции коммуникации

- **Сетевая конфигурация / распределённая память:**
  `send(<что отправляется>, <кому>)` и `recv(<что принимается>, <от кого>)`. В `recv`
  второй аргумент необязателен (данные уже поступили); объём принимаемых данных
  допускается определить после приёма.
- **Общая память:** инициализация дополняется общими данными, соседи не упоминаются;
  локальные данные помечаются индексом $loc$. Обмен — `put(<локальные>, <общие>)` и
  `get(<общие>, <локальные>)`. Исключение одновременного доступа — *критические
  интервалы* (`begin critical section … end critical section`, внутри только одна
  задача). Согласование задач — `barrier` (барьерная синхронизация).

## Распределение данных

Распределить $n$ элементов вектора $a(1:n)$ между $p$ задачами; пусть $n$ делится на
$p$ нацело, $r = n/p$ [[Модели]] §1.2.2:

- **Линейное** — задаче $\mu$ ($1 \le \mu \le p$) отходит фрагмент
  $a((\mu-1)r + 1 : \mu r)$; его элементы соседствовали друг другу и в исходном
  векторе.
- **Циклическое** — $a(\mu : p : n)$: элементы выбираются с шагом $p$ (соседства нет).

Распределение матрицы $A$ зависит от способа хранения (столбцовое — Фортран, строчное
— Си), [[Модели]] §1.2.2 (табл. 1.2):

|              | столбцовое хранение      | строчное хранение         |
|--------------|--------------------------|---------------------------|
| линейное     | $A(:, (\mu-1)r+1 : \mu r)$ | $A((\mu-1)r+1 : \mu r, :)$ |
| циклическое  | $A(:, \mu : p : n)$      | $A(\mu : p : n, :)$       |

### Два правила «хорошего тона» при коммуникациях

1. Отправляемые данные должны лежать в одной области памяти без разрывов. При
   строчном хранении неудачна `send(A(:,1), left)` или `put(A_loc(:,1), a)` — выборка
   столбца идёт с неединичным шагом.
2. Оценивать эффективность объединения коммуникаций (см. линейную/пакетную модели в
   [[топологии-сетей]]): небольшие объёмы выгодно объединять, при $V \gg V_1$ — нет.

Ключевое понятие — **шаг выборки** (расстояние между извлекаемыми элементами в
ячейках); предпочтительны операции с единичным шагом (лучшая конвейеризация).
