# Разложение Холецкого

**Разложение Холецкого** — представление **симметричной положительно определённой**
матрицы $A \in \mathbb{R}^{n \times n}$ в виде

$$A = G G^T,$$

где $G$ — нижняя треугольная матрица с положительными элементами на главной
диагонали. В литературе времён «борьбы с космополитизмом» именуется **методом
квадратного корня** (из-за извлечения корня при нахождении диагонали). По сравнению
с [[LU-разложение|LU-разложением]] требует примерно вдвое меньше работы: оставшаяся
часть алгоритма не содержит решения треугольной подсистемы. См. персону [[Холецкий]].

## Векторные варианты

### Через дахру / gaxpy (jki)

Положим, к $j$-му шагу найдены первые $j-1$ столбцов $G$. Из $A(:,j)=GG^T(:,j)$,
с учётом треугольного вида $G$ и $G^T$, получаем

$$A(j:n,j) = G(j:n,1:j-1)\,G^T(1:j-1,j) + G(j:n,j)\,G^T(j,j). \tag{20}$$

Вводя $v(j:n)=G(j:n,j)\,G^T(j,j)$ и перенося известное вправо — операцию
[[gaxpy-и-saxpy|дахру]]:

$$v(j:n) = A(j:n,j) - G(j:n,1:j-1)\,G^T(1:j-1,j), \tag{22}$$

откуда $G(j,j)=\sqrt{v(j)}$ и $G(j{+}1{:}n,j)=v(j{+}1{:}n)/G(j,j)$. Поскольку
$G(j,j)=v(j)/\sqrt{v(j)}=\sqrt{v(j)}$, вычисление диагонали совмещают с остальным
столбцом для лучшей векторизации. [[Векторные алгоритмы]] §3.1, [[Лекции]] §3.3.2

```
Алгоритм 38 (матричный, через gaxpy):
for j=1:n
  A(j:n,j) = A(j:n,j) - A(j:n,1:j-1)·A^T(1:j-1,j)    % дахру по (22)
  A(j:n,j) = A(j:n,j)/sqrt(A(j,j))                   % по (23)
end for
```

Сравните с Алгоритмом 34 ([[LU-разложение]] через gaxpy): структура та же, но **нет
решения треугольной СЛАУ** — отсюда сокращение сложности. Раскрытие дахру через
столбцовое [[gaxpy-и-saxpy|saxpy]] даёт jki-вид (Алг. 39), через скалярное
произведение — jik. [[Векторные алгоритмы]] §3.1

### Через модификацию матрицы внешним произведением (kji)

Квазиблочное разложение на три сомножителя:

$$\begin{pmatrix} \gamma & v^T \\ v & B \end{pmatrix}
= \begin{pmatrix} \beta & \\ v/\beta & I_{n-1} \end{pmatrix}
  \begin{pmatrix} 1 & \\ & B - \dfrac{v\,v^T}{\gamma} \end{pmatrix}
  \begin{pmatrix} \beta & v^T/\beta \\ & I_{n-1} \end{pmatrix}, \tag{24}$$

где $\beta = \sqrt{\gamma}$. Подматрица $B - \dfrac{v\,v^T}{\gamma}$ — снова симметрична
и положительно определена, $B - \dfrac{v\,v^T}{\gamma} = G_1 G_1^T$ — и тоже раскладывается
по Холецкому; искомая $G = \begin{pmatrix} \beta & \\ v/\beta & G_1 \end{pmatrix}$.
Матричная операция здесь — [[модификация-матрицы-внешним-произведением]].
[[Векторные алгоритмы]] §3.2, [[Лекции]] §3.3.1

```
Алгоритм 41 (матричный, через мм.):
for k=1:n
  A(k:n,k)       = A(k:n,k)/sqrt(A(k,k))                             % k-й столбец G
  A(k+1:n,k+1:n) = A(k+1:n,k+1:n) - A(k+1:n,k)·[A(k+1:n,k)]^T        % мм.
end for
```

По числу арифметических операций алгоритм близок к LU через мм. (Алг. 30): в мм.
вовлекаются и элементы выше диагонали, хотя $G$ туда не распространяется. Длину
векторов в saxpy варьируют, чтобы не выходить за диагональ. [[Векторные алгоритмы]] §3.2

## Параллельные варианты

### На процессорном кольце (Алгоритм 11)

Основан на **gaxpy**-варианте. Расчёт $j$-го столбца $G$ разбит на два шага:
дахру (шаг 1) и деление на корень (шаг 2). Декомпозиция **циклическая по столбцам**
($col=\mu{:}p{:}n$, локальная и глобальная нумерации связаны $j=col(k)$) —
обеспечивает балансировку при треугольном виде $G$. По кольцу пересылается
вычисленный столбец $G$; каждая принявшая задача добавляет одно слагаемое дахру
(7) к своим ещё не найденным столбцам. [[Параллельные алгоритмы]] §2.1

```
Алгоритм 11 (на кольце, общий случай):
while k ≤ L
  if j = col(k) then                                   % задача хранит столбец j
    A_loc(j:n,k) = A_loc(j:n,k)/sqrt(A_loc(j,k))       % G(:,j)
    if j≠n then send(A_loc(j:n,k), right) end if
    for q=k+1:L
      r = col(k)
      A_loc(r:n,q) = A_loc(r:n,q) - A_loc(r:n,k)·A_loc(r,k)   % слагаемое (7)
    end for
    j=j+1; k=k+1
  else
    recv(g(j:n), left)
    if (α≠right) and (β>j) then send(g(j:n), right) end if
    for q=k:L
      r = col(k)
      A_loc(r:n,q) = A_loc(r:n,q) - g(r:n)·g(r)               % слагаемое (7)
    end for
    j=j+1
  end if
end while
```

Простейшая версия (Алг. 10, $p=n$, по одному столбцу на задачу) не систолична
(сначала приём, потом передача) и несбалансирована: задача $\mu$ выполняет $\mu$
векторных операций. Деблокировка обеспечивается первой задачей, отправляющей первый
столбец «эстафетой». Циклическое распределение (Алг. 11) убирает почти все простои
и даёт высокую эффективность ($L-k+1$ saxpy на один приём-отправку).
[[Параллельные алгоритмы]] §2.1

### На процессорной решётке (Алгоритм 14)

Чтобы максимально наследовать от LU на решётке ([[LU-разложение]], Алг. 13), за
основу берут вариант Холецкого **через мм.** (а не gaxpy): в нижнем треугольнике $A$
формируют $G$, в верхнем — $G^T$. Векторный шаблон цикла по $k$:
$\;A(k,k)=\sqrt{A(k,k)}$; $\;A(k{+}1{:}n,k)=A(k{+}1{:}n,k)/A(k,k)$ ($k$-й столбец $G$);
$\;A(k,k{+}1{:}n)=A(k,k{+}1{:}n)/A(k,k)$ ($k$-я строка $G^T$); затем мм.

Строки 01–09 (модификации внешним произведением) совпадают с Алг. 13. Отличия —
извлечение корня на диагонали ($i=j$) с рассылкой $\sqrt{a}$ на юг **и** на восток,
и нахождение строки $G^T$ ($i \le j$): приём $A(i,i)$ с запада, деление, отправка на
юг. По сравнению с LU на решётке добавляются каналы от задач строки $i=1$.
[[Параллельные алгоритмы]] §2.4

```
Алгоритм 14 (на решётке, фрагмент отличий от Алг. 13):
... строки 01-09 совпадают с Алг. 13 (мм. в цикле while) ...
if i=j then                                  % диагональ G
  a = sqrt(a)
  if i≠n then send(a, south); send(a, east) end if
end if
... строки по нахождению столбца G совпадают с Алг. 13 ...
if i≤j then                                  % строка G^T
  recv(a_west, west); if j≠n then send(a_west, east) end if   % A(i,i)
  a = a/a_west
  send(a, south)
end if
```

С учётом симметрии $A$ от работы с верхним треугольником можно отказаться —
топология коммуникаций упрощается (рис. 14б). Все простои, недостатки и способы их
преодоления (укрупнение задач, циклическая декомпозиция блоков) наследуются от
LU на решётке. [[Параллельные алгоритмы]] §2.4
