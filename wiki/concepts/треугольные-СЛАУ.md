# Треугольные СЛАУ

Решение системы $Lx=b$ с **нижней треугольной** матрицей $L \in \mathbb{R}^{n\times n}$
($x,b \in \mathbb{R}^{n\times 1}$). Возникает как заключительный этап решения СЛАУ
общего вида после [[LU-разложение|LU-разложения]] ($Ax=b \Rightarrow Ly=b,\;Ux=y$), а
также **внутри** gaxpy-варианта LU-разложения (там решается унитреугольная подсистема,
[[Векторные алгоритмы]] §2.3). Хотя сложность $O(n^2)$ мала на фоне $O(n^3)$ у
разложений, параллельный вариант актуален: матрица может не помещаться в памяти, а
коммуникации всё равно неизбежны при стыковке с параллельным разложением.
[[Параллельные алгоритмы]] §2.5

## Векторные алгоритмы

### Через скалярное произведение (прямая подстановка, по строкам)

Из $x_1=b_1/l_{11}$ и $x_i=\left(b_i-\sum_{k=1}^{i-1}l_{ik}x_k\right)/l_{ii}$; сумма —
это [[gaxpy-и-saxpy|скалярное произведение]] $L(i,1{:}i{-}1)\cdot x(1{:}i{-}1)$.
Выборка элементов $L$ — **по строкам**. [[Векторные алгоритмы]] §2.1, [[Лекции]] §3.2.1

```
Алгоритм 26 (скалярное произведение):
b(1) = b(1)/L(1,1)
for i=2:n
  b(i) = (b(i) - L(i,1:i-1)·b(1:i-1))/L(i,i)
end for
```

Решение $x$ пишется поверх $b$ (с замещением). «Прямая подстановка» — потому что
индекс $i$ растёт.

### Через saxpy (прямая подстановка, по столбцам)

Найденный $x_1$ сразу подставляется в систему, которая редуцируется; элементы
первого столбца $L$ под диагональю переносятся вправо и умножаются на $x_1$ —
[[gaxpy-и-saxpy|saxpy]]. Выборка — **по столбцам** (удобно при столбцовом хранении).
[[Векторные алгоритмы]] §2.1

```
Алгоритм 27 (saxpy):
for j=1:n-1
  b(j)     = b(j)/L(j,j)
  b(j+1:n) = b(j+1:n) - L(j+1:n,j)·b(j)        % saxpy
end for
b(n) = b(n)/L(n,n)
```

Именно Алгоритм 27 вызывается для решения треугольной подсистемы в gaxpy-варианте
[[LU-разложение|LU-разложения]].

### Уни-треугольный случай и блочный вариант

Если $L$ **унитреугольная** ($l_{ii}=1$), деления на диагональ исчезают (упрощение
Алг. 26/27, задача 2.1.1). Для системы $LX=B$ с $q$ правыми частями лучший выбор —
**блочный** алгоритм (Алг. 28): диагональные блоки $L_{jj}$ остаются треугольными,
тело внутреннего цикла — умножения блоков (по Голубу — основа интенсивного
использования «быстрой» памяти). [[Векторные алгоритмы]] §2.1. См. [[блочные-алгоритмы]].

## Параллельный алгоритм на кольце

Берётся векторный вариант на основе saxpy. Сначала его дорабатывают, вводя
вспомогательный вектор $z$, накапливающий вклады подстановок (Алгоритм 15):

```
Алгоритм 15 (saxpy + накопитель z):
j=0; z(1:n)=0
while j<n
  j=j+1
  b(j) = b(j) - z(j)                         % j-я компонента x
  z(j+1:n) = z(j+1:n) + L(j+1:n,j)·b(j)      % модификация z
end while
```

Декомпозиция $L$ и $b$ — **циклическая по столбцам** ($col=\mu{:}p{:}n$). При наивном
переносе (Алгоритм 16) по кольцу пересылается весь вектор $z$ длины $n$, и вычисления
идут хоть и распределённо, но **последовательно**: актуальный $z$ в каждый момент —
только у одной задачи. [[Параллельные алгоритмы]] §2.5

```
Алгоритм 16 (распределённый, последовательный):
k=0
while k<r
  if (k≠0) and (μ≠1) then recv(z, left) end if
  k=k+1
  j=col(k)
  b_loc(k) = b_loc(k) - z(j)
  if j<n then
    z(j+1:n) = z(j+1:n) + L_loc(j+1:n,k)·b_loc(k)
    send(z, right)
  end if
end while
```

### Истинно параллельный вариант (Алгоритм 17)

Ключевая идея: не нужно пересылать весь $z$ — по кольцу пускают **короткий вектор $w$
длины $p$** (по одному элементу на задачу). Локальный накопитель $z$ длины $n$
остаётся в задаче. $j$-я компонента $x$ через скалярные произведения фрагментов:

$$x(j) = b(j) - \sum_{l=1}^{\min\{p,\,j-1\}} L(j,\,l{:}p{:}j{-}1)\cdot x(l{:}p{:}j{-}1).$$

Накопление $z_l^{(k)} = z_l^{(k-1)} + L(1{:}n,\,l{+}(k{-}1)p)\,x(l{+}(k{-}1)p)$ (11)
организовано так, что в момент вычисления

$$x(j) = b(j) - w(\mu) - z_\mu^{(k-1)}(j), \tag{14}$$

где $w(\mu)=\sum_{l=1}^{\mu-1} z_l^{(k)}(j) + \sum_{l=\mu+1}^{p} z_l^{(k-1)}(j)$ (13).
После отыскания $x(j)$ задача $\mu$ дозаполняет элементы $w$ и шлёт его дальше.

```
Алгоритм 17 (параллельный, циркулирует вектор w длины p):
k=0
while k<r
  if (k≠0) and (μ≠1) then recv(w, left) end if
  k=k+1
  j=col(k)
  b_loc(k) = b_loc(k) - w(μ) - z(j)                       % по (14)
  if j<n then
    q = min{n, j+p-1}
    z(j+1:q) = z(j+1:q) + L_loc(j+1:q,k)·b_loc(k)         % по (11), часть для w
    if k<r then
      w(1:μ-1) = w(1:μ-1) + z(j+p-μ+1:j+p-1)              % верхняя часть w
      w(μ) = 0                                            % своя ячейка освобождается
    end if
    w(μ+1:p) = w(μ+1:p) + z(j+1:j+p-μ)                    % нижняя часть w
    send(w, right)
    if q<n then z(q+1:n) = z(q+1:n) + L_loc(q+1:n,k)·b_loc(k) end if  % остаток z
  end if
end while
```

Образ: вектор $w$ — поезд на кольцевой дороге; на каждой станции (задаче)
освобождается «свой» вагон (ячейка $w(\mu)$ обнуляется), остальные догружаются.
Формирование $w$ последовательно, но он короткий ($p \ll n$), а модификация хвоста
$z(q{+}1{:}n)$ идёт по задачам независимо — отсюда параллелизм.
[[Параллельные алгоритмы]] §2.5

**Деградация на последних оборотах.** Число арифметических операций с $z$ убывает
линейно, а объём пересылок ($p$ чисел) постоянен → эффективность к концу падает.
Лечение — гибрид: основная часть по Алг. 17 до оборота $r_0$, заключительная по
Алг. 15 (сбор $z$ и хвоста системы в одну выделенную задачу). [[Параллельные алгоритмы]] §2.5
